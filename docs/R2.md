# Setting up Cloudflare R2 storage

This guide takes you from nothing to finished videos being served from Cloudflare R2.

> **Not yet tried on real R2.** The app's side was built and tested against a stand-in for R2. The Cloudflare steps below are written from Cloudflare's documentation, and the names of buttons in their dashboard may differ slightly. If a step doesn't match what you see, tell me what the screen shows.

## Why do this

By default a finished video is stored on the computer vidshare runs on. When a friend opens a share link, the video travels from that computer, through the Cloudflare Tunnel, to them.

With R2 on:

- Each finished video is uploaded to your R2 bucket, and the local copy is deleted.
- A friend's browser is sent straight to R2 with a link that works for about an hour. The video never passes through the tunnel or your home internet.
- **This is what keeps you inside Cloudflare's rules:** they don't allow video through the tunnel itself.
- Daily backups of the database also go to the bucket, so they survive losing the computer.

## What it costs

R2 has a free allowance, renewed every month:

| | Free each month |
|---|---|
| Storage | 10 GB |
| Uploads and changes | 1 million |
| Downloads and reads | 10 million |
| Sending data out to viewers | Free, with no limit |

A 200 MB video kept for 48 hours uses about 0.013 GB of the monthly storage allowance, so the free allowance covers hundreds of videos a month. Cloudflare asks for a payment card when you turn R2 on, even if you never leave the free allowance.

## Step 1: turn on R2 and create a bucket

1. Sign in at [dash.cloudflare.com](https://dash.cloudflare.com).
2. In the left menu, open **R2 Object Storage**. If it's your first time, follow the prompts to turn R2 on (this is where it asks for a card).
3. Press **Create bucket**.
4. **Name:** for example `vidshare`. Lowercase letters, numbers and dashes only.
5. **Location:** leave it on Automatic.
6. **Storage class:** leave it on Standard.
7. Create it. Leave public access **off**: vidshare hands out private, signed links, so the bucket never needs to be public.

## Step 2: create an access key

1. On the R2 overview page, find **Manage R2 API Tokens** (or **API** → **Manage API tokens**).
2. Press **Create API token** (an *Account* token is fine).
3. **Permissions:** choose **Object Read & Write**.
4. **Specify bucket:** choose "Apply to specific buckets only" and pick your bucket.
5. **TTL:** Forever (or a date you'll remember to renew).
6. Create it. Cloudflare now shows, **once**:
   - **Access Key ID**
   - **Secret Access Key**

   Copy both somewhere safe before leaving the page.
7. Also copy your **Account ID**. It's on the R2 overview page, and it's the first part of the address shown as "S3 API": `https://<account id>.r2.cloudflarestorage.com`.

You now have four values: Account ID, bucket name, Access Key ID, Secret Access Key.

## Step 3: two settings on the bucket

vidshare tries to set these two for you during its connection test. An access key limited to "Object Read & Write" usually isn't allowed to change bucket settings, so the test will mark them "not available". That's fine: set them by hand once.

### a) Let your site read files (CORS)

Needed for the **Share video** button on a phone, which fetches the file before handing it to WhatsApp or Messages. Without it, Download and share links still work; only that button doesn't.

1. Open the bucket → **Settings** → **CORS policy** → **Add CORS policy**.
2. Paste this, with your own address in place of `https://your-domain.example` (the same as `JOYSHARE_PUBLIC_URL` in `.env`):

```json
[
  {
    "AllowedOrigins": ["https://your-domain.example"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["Content-Length", "Content-Range"],
    "MaxAgeSeconds": 3600
  }
]
```

### b) Delete leftover videos automatically

vidshare deletes expired videos from the bucket itself. This rule is a safety net in case it ever can't.

1. Open the bucket → **Settings** → **Object lifecycle rules** → **Add rule**.
2. **Prefix:** `outputs/` (videos only; this keeps the rule away from your backups, which live under `backups/`).
3. **Action:** delete objects **4 days** after they were uploaded.

## Step 4: connect vidshare

1. Open vidshare and go to **☰ → Admin panel → Storage**.
2. Type the four values: Account ID, Bucket name, Access Key ID, Secret Access Key.
3. Press **Save and test**. vidshare then:
   - writes a small test file to the bucket,
   - reads it back through a signed link,
   - deletes it,
   - tries to set the two bucket settings from step 3.

   The first three must pass. The last two may say "not available on this storage (optional)" if you set them by hand.
4. When the test passes, press **Serve new files from R2**.

From now on new videos go to R2. The Storage tab shows how many files are in the bucket.

## Step 5: check that it works

1. Make a short video. During progress you'll see an extra step, **Uploading to storage**.
2. Press **Get a link for friends** and open the link in a private window. The video should play.
3. Optional proof: in the Cloudflare dashboard, open the bucket. You'll see a file under `outputs/`.
4. On your phone, try **Share video**. If it never appears or does nothing, the CORS policy from step 3a is the likely cause.

## Good to know

- **The switch only unlocks after the test passes.** If you later change any of the four values, vidshare goes back to serving from the server until you test again.
- **Going back is safe.** Press **Go back to this server** any time. Videos already in R2 keep working until they expire.
- **If an upload fails,** that video stays on the server and you get an alert (if alerts are set up).
- **The Secret Access Key is stored encrypted** and never shown again. For the strongest protection set `JOYSHARE_SECRET` in `.env` (see the [setup guide](SETUP.md)).
- **Backups:** once R2 is tested, the daily database backup also goes to `backups/` in the bucket, keeping the newest 14. This happens even if you serve videos from the server.
- **Replacing the key:** create a new access key in Cloudflare, type the new ID and secret in the Storage tab, press **Save and test**, then delete the old key in Cloudflare.

## If the test fails

| The step that failed | Likely cause |
|---|---|
| **Write a test file** | Wrong Access Key ID or Secret, wrong bucket name, or the key isn't allowed to write to that bucket. |
| **Read it through a signed link** | Wrong Account ID (the address is built from it), or the server's clock is far off. |
| **Delete it** | The key has read-only permission. Create one with Object Read & Write. |
| **Allow this site to read files** / **Delete leftovers** | Expected with a limited key. Set them by hand (step 3). |
| "Cloud storage isn't fully set up" | One of the four values is empty. |

The message under each failed step shows what Cloudflare answered. Send it to me if it isn't clear.
