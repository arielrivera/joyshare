joyshare

A private web app on your own server. Paste a video link from your phone or any computer, choose a size, and get back an MP4 to send with WhatsApp or iMessage, or a 48-hour link your friends can open in a browser.

  1. Open the home-screen app on your iPhone, or use the iOS share sheet shortcut. Unlock with Face ID.
  2. Paste a link from X (Twitter), YouTube, TikTok, Instagram or Facebook. The server reads the video's details and shows the title, author, length and the estimated size for each preset.
  3. Pick a size, such as Share 720p, Small 480p or one shrunk to fit a size you choose, or cut just a clip. Anything over 200 MB is refused.
  4. Watch live progress. When it finishes you see the real file size, and you can make it smaller or sharper and run it again.
  5. Send it: Share opens the iPhone share sheet (WhatsApp, Messages, Save to Photos), Download saves the file, and Copy link gives friends a 48-hour viewing page.

Architecture

Your devices never talk to the server's IP. They reach your domain at Cloudflare, and the server holds an outgoing connection open to Cloudflare. That is why the server can move anywhere. The numbers follow one video from your link to your friends.

Hosting and moving the server

The goal is to move between a Mac, a Linux server, a cloud server or a Raspberry Pi in about fifteen minutes, with the domain following on its own. Two choices make that work: everything ships as Docker containers, and the domain is tied to a Cloudflare Tunnel, not to an IP address.

Docker containers

Pros

  • The same setup runs on Ubuntu, macOS and a Pi. Python, ffmpeg and yt-dlp come inside the image, so nothing is installed by hand on the host.
  • Moving is three steps: pack the data volume into one backup file, copy it and the .env file over, run docker compose up -d.
  • Updating yt-dlp or rolling back is a rebuild, not a messy system upgrade.
  • Each part (web, worker, tunnel) restarts on its own if it crashes or the machine reboots.

Cons

  • On a Mac, Docker runs inside a small Linux VM (OrbStack or Docker Desktop). It works well, but ffmpeg can't use the Mac's hardware video encoder from inside it, so re-encoding is CPU-only.
  • The Pi needs a 64-bit OS and an ARM build of the image. We build for both Intel/AMD and ARM, so this is handled once.
  • One more tool to learn (a handful of commands, all written down in the setup guide).
  • Images take a few hundred MB of disk.

Verdict: use Docker. The ease of moving matters more than the small speed cost, and most of our presets avoid re-encoding anyway.

Moving to a new machine

  1. Install Docker on the new machine (Docker Desktop on a Mac).
  2. On the old machine run ./joyshare backup. It stops the app and packs the data volume and .env into one file.
  3. Copy that file and .env over, then run ./joyshare restore. It starts everything.
  4. The tunnel signs in with the same token and Cloudflare sends your domain to the new machine. No DNS change.
  5. Run ./joyshare retire on the old machine so it stays off. Two copies at once would split the database; joyshare notices and alerts if it happens. The steps are in docs/MOVING-MAC.md and docs/MOVING-LINUX.md.

An internet connection without a static IP

The tunnel solves this. Your server opens an outgoing connection to Cloudflare, so its IP can change as often as it likes, you don't forward any ports on your router, and it works even when your ISP shares one public IP across customers (CGNAT). The fallback without Cloudflare is a dynamic DNS script that updates your domain's IP every five minutes, plus port forwarding on the router. That works on most connections, but not behind CGNAT.

Access: only your devices

  • Roles. Admin (you) sees the admin panel and everyone's activity. Members, added later, see only their own videos. The first account created is the admin.
  • Passkeys. The first device registers with a one-time setup code printed in the server log. After that, sign-up is closed.
  • Adding a device. A signed-in device creates a QR code that works once, for 10 minutes. This is also how family members get added later.
  • iCloud sync. Your passkey syncs through iCloud Keychain, so any device on your Apple ID can sign in. Windows and Android devices use the QR flow.
  • iOS Shortcut and scripts. Each gets its own access token, listed and revocable on a Devices page.
  • View as member. An admin can use one device as a regular member, to see exactly what members get, and switch back. The server only allows it for admins.
  • No extra lock. Cloudflare Access was skipped. If added later, only in front of the admin panel; share links under /v/ would stay outside it.
  • Share links. These are the only public pages: a random 128-bit ID, a 48-hour expiry, and a viewer page with a thumbnail preview for WhatsApp and iMessage.

Connected accounts (cookies)

Each user can upload a cookie file per platform under ☰ → Connected accounts. It is optional.

  • Private to each user. A cookie file is used only for the downloads of the person who uploaded it. It is never shared with other users, and no one else can see it in the app, including the admin.
  • Stored encrypted in the data folder, and removable at any time with one tap.
  • File reuse stays per user. A video fetched with one person's cookies is never handed to another user's request.
  • Status per platform: Connected, Expired or Not connected. An alert goes to that user when a platform stops accepting their cookies.
  • Without cookies, the app still tries. Public videos often work. The error message says clearly when a video needed a sign-in.

Encoding speed

Inside Docker, ffmpeg uses the CPU only. That is unlikely to be a problem: most presets don't re-encode at all, and an Apple Silicon CPU converts 720p video several times faster than it plays. Real times so far on the server have been fast enough.

If it does prove slow, the plan is an optional Mac encoder helper: a small program running on macOS itself, outside Docker, that uses the Mac's own ffmpeg and hardware encoder (VideoToolbox). The worker checks at startup whether the helper is there. If it is missing, or a hardware encode fails, the job runs on the CPU in the container. One trade-off: hardware encoding is faster but gives slightly lower quality at small file sizes, so "Fit a size" stays on the CPU encoder.

Where videos are stored and served

Every video is first made on the server and saved in the data volume. The only question is where phones fetch the file from. The share link (yourdomain.com/v/…) and its viewer page look the same either way.

Mode A: from the server Available

  • Phones get the page and the video from the server.
  • For trying it out, a server on your own network, or a server with its own web server (Caddy) instead of the tunnel.
  • Nothing extra to set up.

Mode B: from R2 In use

  • When a job finishes, the worker also uploads the MP4 to an R2 bucket.
  • The viewer page, your own Share and Download buttons, and the player all use signed R2 links. Each link is created fresh when the page is opened and lasts about an hour. The share page itself stops working after 48 hours.
  • The video bytes never pass through Cloudflare's regular proxy, so this follows their terms. R2 is the product they point to for serving files like this.
  • R2 deletes files after 2 days on its own. It's free under 10 GB, about 50 videos at the 200 MB maximum.

You switch modes in the admin panel. It shows whether R2 is set up, walks you through creating the bucket and keys if it isn't, and only enables the switch after a connection test passes. Turn on R2 before the app is reachable through the tunnel.

A cleanup task runs every 5 minutes, and once at startup. It runs on a scheduler built into the worker container, not as a cron job on the host, so it moves with the app and needs no host setup. It deletes expired files and checks disk use. At 90% full it sends an alert. At 95% it stops accepting new jobs until space is freed.

How yt-dlp updates itself

  1. Once a day, and when you press Update now, the scheduler checks for a newer yt-dlp release.
  2. It installs the new version into the data folder, so the container doesn't need rebuilding.
  3. The worker finishes its current job, restarts, and runs a test download.
  4. If the test fails, it goes back to the previous version and sends an alert. If it passes, you get a low-priority "updated" alert.

Also in place

  • Lockout recovery. If you lose every passkey, ./joyshare setup-code on the server prints a new one-time code.
  • Last admin protection. The only admin can't be removed or demoted.
  • Per-user limits (still planned): daily job count and size limits per person.
  • Settings live in the database, so changes apply right away and travel with a backup. Secrets such as R2 keys are stored encrypted.

Glossary

OrbStack
A Mac app that runs Docker containers, as a replacement for Docker Desktop. It starts faster and uses less memory and battery. Free for personal use. Downsides: Mac only, closed source, and from a small company. Optional. Docker Desktop works fine. Worth considering on a Mac that runs all day.
Cloudflare Access
A sign-in gate that runs at Cloudflare, before a visitor reaches your server. You list the allowed email addresses. A visitor enters their email, gets a one-time code, and is let through for a set time, for example 30 days. Free for up to 50 users. Good: strangers and bots never touch the app. Cost: a second sign-in step every few weeks, and the iOS Shortcut needs extra setup. Suggestion: skip it at first, or put it only in front of the admin panel.
Residential proxy
A paid service that sends your server's requests out through an ordinary home internet connection somewhere else. YouTube or Instagram then see a home IP instead of a data-center IP and block it far less. yt-dlp supports it with one setting (--proxy). They usually charge per GB, a few dollars per GB. Only needed if a cloud server keeps getting blocked. A server on your own internet connection already has a residential IP, for free.
Cloudflare Tunnel
A small program (cloudflared) on your server opens an outgoing, encrypted connection to Cloudflare. Visitors go to your domain at Cloudflare, and Cloudflare passes the traffic down that connection. Your server needs no public IP, no open ports and no router setup. Free. It needs your domain's DNS to be hosted on Cloudflare, which is also free. Recommended because it solves the changing IP, makes moving servers trivial, hides your server's address, and gives free HTTPS.
Worker process
A separate program that runs alongside the website. When you submit a link, the website just adds a row to the jobs table and answers right away. The worker picks up that row, runs yt-dlp and ffmpeg (which can take minutes), and writes progress back. A slow download or a crash never freezes the website, and queued jobs survive a restart.
Redis, arq, RQ
Redis is a very fast in-memory database, often used as a job queue. arq and RQ are Python libraries that put jobs on a Redis queue and run them in workers. arq is the async version, RQ is the simpler classic one. Worth switching to with many users or several workers. For one user it's an extra container with no benefit.
SQLite WAL mode
SQLite is a database stored in one file. In "write-ahead log" mode, changes are first appended to a side file and merged in later. Readers keep working while someone writes. The worker updates progress many times a second while the website reads it. With WAL they don't block each other.
SvelteKit (static)
Svelte is a frontend framework that compiles your components into small, plain JavaScript. SvelteKit adds pages and routing. The "static" build outputs ordinary HTML, CSS and JS files with no Node server in production. Three.js draws the 3D progress scenes. Considered, not used: the interface stayed plain HTML, CSS and JavaScript, which needs no build step.
SSE (Server-Sent Events)
A browser feature where the page keeps one normal HTTP request open and the server pushes small updates down it, like "downloading 42%". It reconnects automatically. Progress only flows from the server to you, so SSE is simpler than WebSockets, works through Cloudflare without extra setup, and needs no polling.
ntfy
An open-source push notification service. The server sends a message to a "topic" and the ntfy app on your iPhone shows it as a notification. Free on ntfy.sh, or you can host it yourself.
Uptime Kuma
A free, open-source dashboard you host yourself. It checks your site every minute and alerts you when it goes down. It has to run on a different machine than the one it watches.
healthchecks.io
A hosted "dead man's switch". Your server pings it every few minutes, and if the pings stop it alerts you, including through ntfy. The free plan covers 20 checks, which is plenty here.
Backblaze B2 / Cloudflare R2
Cheap cloud storage for backups. B2: first 10 GB free, then about $6 per TB per month. R2: 10 GB per month free and no fee for downloading your data back. Our database backups will be far under 10 GB, so either is free in practice.

Risks and gaps

Cloudflare and video (resolved). Cloudflare's CDN terms ask non-Enterprise sites to serve video through products such as R2 or Stream, not the regular proxy. With R2 mode on, video comes straight from R2 and only small pages pass through the tunnel. Rule: turn R2 on before the app is reachable through the tunnel.
  • Blocking Platforms change often. yt-dlp updates every night, cookies can be uploaded per platform, and a proxy setting is ready if needed.
  • Security Allow-listed platforms only, no shell commands built from user input, private network addresses blocked, sign-in rate limits, secure cookies, a content security policy and CSRF protection.
  • Server SSH keys only, automatic security updates, firewall closed to everything (the tunnel needs no open ports).
  • Load Limits on length and size, at most 2 jobs at once, and fast ffmpeg settings.
  • Phone UX Three.js loads only when needed and pauses when the tab is hidden. "Reduce motion" turns it off.
  • Legal Personal use only. Share links are unlisted and expire.
  • Domain Passkeys are tied to the domain name. Pick the final domain before registering devices, because changing it later means registering every device again. Passkeys made at localhost don't carry over.
  • Mac restart Docker on a Mac starts only after someone logs in. With FileVault disk encryption on, a Mac can't log in by itself after a power cut, so the app stays down until you do. On Linux, Docker starts by itself. Uptime Kuma will alert you, and the troubleshooting guide covers the options.
  • Cookies Use a spare account for platform cookies, not your main one. Platforms sometimes restrict accounts used for automated downloads.
  • Share sheet The iPhone Share button works. It has to load the whole file into memory first, so it may fail near 200 MB; the size where it stops working hasn't been found yet.
